Design decisions

Decision Rationale Tradeoff Evidence
Keep research roles configurable rather than hard-coded. Scenario-specific proposal/coder/runner/summarizer can share iterative workflow machinery. Behavior depends on configured implementations and external credentials/environments. RDLoop (L31)
Exchange factor data via Parquet artifacts. Runner documents cross-environment NumPy pickle compatibility and writes combined factors to Parquet. Artifact schemas/environment templates remain integration contracts. QlibFactorRunner (L25) / QlibFBWorkspace (L13)

Qlib factor R&D iteration

Qlib training/backtesting is an external integration invoked via qrun inside Docker/Conda; it is not a native broker simulator. Roles are configured objects whose complete implementations are outside this representative trace.

Strengths and limits

Strengths

  • Empty or overly correlated newly generated factors are explicitly rejected before experiment evaluation. QlibFactorRunner (L25)

Limitations

  • Agent R&D automation is not live order execution; no exchange/account/order workflow is established in the reviewed research path. QlibFBWorkspace (L13) / RDLoop (L31)
  • Recorded credentials/MCP/Kaggle failures and configured environment prerequisites remain observable despite current completion exclusions. docs/validation.md (L16)

Validation scope

The linked validation and command records preserve actual historical runs and user-authorized exclusions. This source/document review does not rerun application tests, establish live trading readiness or rank benchmark performance. Current data, credential and runtime prerequisites remain material.
